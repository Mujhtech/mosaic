# Privacy

Mosaic's analytics are built around data minimization: a closed event
catalog, no advertising identifiers, no IP-derived location, and
ingestion-boundary rejection of values shaped like emails, phone numbers,
tokens, or payment identifiers. This guide covers the identity model and the
operator-facing privacy operations.

## Identity model

Two identity kinds exist:

- **Installation**: a random per-install identifier generated by the SDK,
  with a generation counter that advances on reset. Always present on events.
- **Application user**: an optional identifier your app supplies via the
  SDK's `identify` API (1–256 code points; values that look like emails or
  phone numbers are rejected at ingest). Anonymous-by-installation is the
  default.

Identities are stored as opaque references linked through generation-aware
aliases. Event-time identity snapshots are never rewritten by later
`identify` or `reset` calls. SDK-side identity and queue persistence is
app-private and excluded from device backups.

## Export

To answer a data-access request, an Organization owner runs an identity
export from the data-privacy surface
(`.../analytics/{environmentId}/data-privacy`) or the API:

1. `POST /v1/projects/{projectId}/analytics/privacy/preview` — shows affected
   event/session counts and returns a request digest.
2. `POST /v1/projects/{projectId}/analytics/privacy/exports` — starts an
   export job (NDJSON or CSV).
3. Poll `GET /v1/projects/{projectId}/analytics/jobs/{jobId}` and download
   via `.../download`.

Export artifacts are private object-storage files that expire after seven
days.

## Deletion

Identity deletion is a two-step, owner-only operation: run the preview, then
`POST /v1/projects/{projectId}/analytics/privacy/deletions` with the
preview's `requestDigest` and `confirm: true`. Deletion hard-deletes the
identity's events and sessions, removes identity links, and completes only
after affected aggregate buckets (including Experiment exposure buckets whose
conversions referenced the identity) are rebuilt. Audit records store digests
and counts, never the raw submitted identity.

## Retention

- Raw events: per-Environment `rawRetentionDays`, 30–730 days (default 180),
  enforced from received time by the worker.
- UTC daily aggregates and privacy audit rows: 24 months, not configurable.
- Ingestion refuses events older than seven days.

## Disabling collection

Set `collectionEnabled: false` for an Environment (same settings surface) to
stop ingestion for it. Collection is off by default for every Environment.

## Backup implications

Deletion operates on the live database. Backups taken before a deletion still
contain the deleted data, and Mosaic does not manage backup retention or
encryption: backup artifacts are plaintext dumps of configuration and
analytics data, and the operator is responsible for encrypting them,
restricting access, and setting a retention policy that ages out pre-deletion
backups in line with their compliance obligations. See
[docs/backend/operations/backup-restore.md](../backend/operations/backup-restore.md).
