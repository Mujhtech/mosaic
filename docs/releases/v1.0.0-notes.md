# Mosaic v1.0.0 Release Notes

> **DRAFT — pending Stage 6 review.** These notes describe the intended
> v1.0.0 release. No `v1.0.0` tag exists yet; content is subject to the
> Phase 8 review gate (`docs/reviews/phase-8.md`).

Mosaic v1.0.0 is the first General Availability release: an open-source,
self-hostable platform for creating, publishing, and experimenting with
native paywalls across Flutter, SwiftUI, and Jetpack Compose — one
platform-neutral protocol, three native renderers, one Studio.

## Headline capabilities

- **Native paywalls**: visual Studio editing, rendered natively on Flutter,
  SwiftUI, and Jetpack Compose — no WebView, no executable code in remote
  configuration.
- **Remote configuration and publishing**: drafts, immutable paywall
  versions, immutable per-Environment Configuration Releases, rollback that
  creates a new release, digest-addressed assets.
- **Placements and targeting**: deterministic first-match rule sets with
  three-state (true/false/unknown) condition evaluation, percentage rollout,
  offline on-device decisions, and a persistence-free simulator.
- **Provider-independent commerce**: Products and Entitlements as separate
  concepts; RevenueCat, custom, StoreKit 2, and Google Play Billing provider
  paths; four-state Entitlement results (provider failure is never rendered
  as "not entitled").
- **Analytics**: closed event catalog (Analytics Event 1 and 2), off by
  default per Environment, ingestion-boundary data minimization, funnels and
  breakdowns, export and deletion jobs.
- **Experiments**: variants pinned to immutable paywall versions,
  deterministic hash assignment, exposure-only-after-presentation, mutual
  exclusion groups, descriptive Wilson/Newcombe statistics with no winner
  declaration, SRM warnings, emergency stop.
- **Self-hosting**: one `docker compose up` yields a complete installation;
  all configuration via environment variables; strict production startup
  validation.

## What changed in Phase 8 (operational hardening)

Phase 8 was a feature-frozen hardening phase between `v1.0.0-rc.1` and GA.
Full detail in [CHANGELOG.md](../../CHANGELOG.md). Highlights:

- **Configuration validation**: strict startup validation with structured,
  secret-free errors; production mode rejects unsafe defaults (wildcard/HTTP
  CORS, plaintext database or object-storage transport, missing secrets).
- **Health and readiness**: `GET /health/live` with build identity;
  `GET /health/ready` checking PostgreSQL, object storage, migration
  compatibility, and encryption configuration; worker health endpoints;
  a distroless-friendly healthcheck probe.
- **Graceful shutdown**: readiness flips to draining first, with separate
  budgets for HTTP drain, telemetry flush, and pool close; worker jobs commit
  failure records even during SIGTERM.
- **Migration preflight**: `migrate preflight`, `up-to`/`down-to`, richer
  `status`, advisory locking, per-step timeouts, `--confirm` for destructive
  operations; irreversible down migrations detect affected data and refuse,
  naming the restore path; migration 00018 reshaped so upgrades do not block
  ingestion on populated databases.
- **Backup and restore tooling**: PostgreSQL and object-storage
  backup/restore scripts with checksums and post-restore verification; a
  Mosaic backup is defined as database + object storage + keyring.
- **Key rotation**: the `keyring` command (`validate`, `inspect`, `rotate`)
  for the AES-256-GCM provider-credential keyring.
- **Worker reliability**: expired-lease reclamation and retry-with-backoff
  for Experiment scheduling jobs (previously silent job loss), round-robin
  job families, queue-depth and oldest-age metrics.
- **Rate limiting and trusted proxies**: per-surface limits with
  `Retry-After`; `X-Forwarded-For` honored only from configured trusted
  CIDRs, closing a rate-limit bypass.
- **Observability**: HTTP and pool metrics, worker gauges, delivery 304
  ratio, object-storage spans, version attributes on the OTel resource, and
  vendor-neutral alert definitions.
- **Protocol contracts approved**: all v1 contracts flipped from
  `releaseCandidate` to `approved` with a documented deprecation lifecycle;
  protocol schemas embedded in the API binary (`go:embed`), eliminating
  image-packaging drift.
- **SDK safe-failure hardening**: crash-path guards (dispose/lifecycle/
  persistence failures degrade safely), iOS 15 compatibility fix with a
  dedicated compile check, version-header reconciliation across platforms,
  and honest pre-1.0 installation documentation.
- **Experiment conversion-attribution fixes**: the analytics ingestion
  boundary now enforces the canonical per-event attribution allow-lists and
  rollout-tuple atomicity (the Phase 6 blocker); SDKs emit Experiment
  conversions on Analytics Event 2 with the complete tuple, and fallback
  conversions are tuple-free on all platforms.

## Known limitations

The complete owner-accepted register, with workarounds, is
[docs/known-limitations.md](../known-limitations.md). Summary:

- **All three SDKs are pre-1.0 and unpublished** — install by git pin or
  local path (D6).
- **Android**: dependency versions frozen for GA; the instrumentation suite
  requires a device or emulator (that evidence layer is "not demonstrated"
  headless).
- **Flutter**: analytics runtime state is a process-wide static map (one
  client per Environment is the documented usage); per-decode isolate
  startup cost; quadratic queue accounting on the bounded overflow path; the
  commerce router's stream is not closed by `dispose()` (bounded leak on
  repeated reconfigure).
- **iOS**: the iOS 15 floor is compile-verified, not runtime-verified;
  `refresh()` is not cancellable (bounded by request timeout); background
  analytics flush is best-effort; lifecycle registries are retained for the
  process; unreachable persistence degrades to in-memory with a diagnostic.
- **Protocol**: browser-contract generation not extended to the Phase 5–7
  contracts (server-side validation covers them); Commerce Provider fixtures
  are tool-verified but not yet SDK-consumed; **three Experiment guardrail
  metrics (`product_unavailable`, `provider_unavailable`,
  `paywall_render_failure`) always report zero** — their numerator events
  cannot carry the attribution tuple under the approved Analytics Event 2
  contract; fixed by Analytics Event 3 post-GA.

## Not in v1

- Mosaic Billing (Phase 9)
- AI assistance (Phase 10)
- Kubernetes, Helm, or Terraform deployment
- Registry-published SDKs (pub.dev, CocoaPods trunk, Maven Central)
- Live-verified store purchases: commerce adapters are implemented and
  contract-tested but not verified against the RevenueCat sandbox, Apple
  sandbox, or a Google Play test track (D10)
- Redis, release channels, Analytics Event 3, published latency SLOs
  (measured and recorded, published post-GA per D8)
